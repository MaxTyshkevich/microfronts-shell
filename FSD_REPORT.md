# Отчёт: переход Shell на FSD

Дата: 21 сентября 2026 года. Ветка: `refactor/shell-fsd`.

## Результат

Плоская структура исходников заменена слоями `app`, `pages` и `entities/session`. Монолитный `App.tsx` разделён по ответственности. Поведение страниц, контракт микрофронтов, адреса маршрутов и русские строки интерфейса сохранены.

| Раньше | Теперь |
| --- | --- |
| `src/App.tsx`: создание приложения | `app/entrypoint/create-app.tsx` |
| `src/App.tsx`: жизненный цикл сессии и QueryClient | `app/providers` |
| `src/App.tsx`: routes и guards | `app/routes` |
| `src/App.tsx`: общая навигация и выход | `app/ui/shell-layout.tsx` |
| `src/App.tsx`: регистрация и загрузка remote | `app/integrations/remotes` |
| `src/App.tsx`: страницы аккаунта и remote | `pages/account`, `pages/remote` |
| `src/AuthPage.tsx` | `pages/auth/ui/auth-page.tsx` и `pages/auth/lib/safe-return-to.ts` |
| `src/auth-api.ts` и useSession из App | `entities/session/api` и `entities/session/model` |
| `src/config.ts` | `app/config/runtime-config.ts` |
| `src/cart-key.ts` | `app/lib/guest-cart-key.ts` |
| `src/RemoteBoundary.tsx` и `src/remote-props.ts` | `app/integrations/remotes` |
| `src/styles.css` | `app/styles/global.css` |

`src/main.tsx` остаётся точкой входа. Пустой по смыслу `remotes.d.ts`, содержавший только комментарий, удалён. Слайсы предоставляют публичные `index.ts`. Страницы получают данные и callbacks через props; содержимое remote передаётся через children. Обратных импортов из pages/entities в app нет.

Сохранены отмена старых запросов, замена и очистка QueryClient, generation для перемонтирования дерева, проверка ожидаемого клиента при восстановлении сессии и ротация гостевого ключа. Новые библиотеки и состояние через дополнительный store не добавлялись.

## Автоматический контроль архитектуры

Добавлена команда `npm run check:architecture`, включённая в GitHub Actions. Скрипт использует существующий TypeScript для разбора импортов и разрешения путей. Он проверяет структуру слоёв, направление зависимостей, изоляцию слайсов, публичные API и отсутствие локальных импортов за пределами слоёв.

Проверено на временных нарушениях: импорт вверх, cross-slice re-export, глубокий импорт в entity, динамический импорт вверх и импорт файла вне src отклоняются. Временные файлы удалены после проверки.

## Документация и runtime-конфиг

Обновлены README и [архитектура](docs/architecture.md), добавлено [объяснение runtime-конфига](docs/runtime-config.md). В AGENTS актуализирован путь реэкспорта контрактов и локальное описание состояния миграции.

Runtime-конфиг — JSON с адресами API и remote, который браузер читает перед запуском приложения. Он нужен для отделения настроек подключения от JavaScript. Но в текущей инфраструктуре production-JSON создаётся **при сборке**, а Docker просто отдаёт готовый файл. Изменение переменных окружения готового контейнера этот JSON не меняет. Для настоящего переключения окружений без пересборки понадобится отдельная доставка JSON или его генерация при старте контейнера.

Генерация конфига при старте контейнера, изменение backend, контрактов или способов развёртывания не входят в этот рефакторинг.

Дополнительно GitHub CLI не установлен, а неинтерактивные учётные данные GitHub API недоступны. Создание PR требует доступного авторизованного клиента. Успешные локальные проверки не означают успешного прохождения удалённого CI.
