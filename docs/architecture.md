# Архитектура Shell

Shell собирает приложение, управляет навигацией и сессией и подключает `catalog/CatalogApp` и `cart/CartApp` по URL. Бизнес-логика каталога и корзины остаётся в remote. Исходники соседних репозиториев не импортируются.

## FSD

Используются только необходимые слои Feature-Sliced Design: `app → pages → entities`. Слои `features`, `widgets` и `shared` пока не нужны; `processes` не используется.

```text
src/
  main.tsx                         React root и запуск после чтения конфигурации
  app/
    entrypoint/create-app.tsx      Сборка providers, router и remote
    config/runtime-config.ts       Чтение и проверка runtime-config.json
    providers/                     HostProvider и фабрика QueryClient
    routes/                        Маршруты, guards и адаптеры страниц
    integrations/remotes/          Регистрация, lazy-загрузка, boundary и типы props
    lib/guest-cart-key.ts           Хранение и обновление гостевого ключа
    ui/shell-layout.tsx            Навигация, проверка сессии и выход
    styles/global.css              Стили Shell
  pages/
    auth/                          Форма входа/регистрации и безопасный returnTo
    account/                       Представление аккаунта
    remote/                        Общая оболочка каталога и корзины
  entities/
    session/                       Тип Session, auth API и useSession
```

`app` разделён непосредственно на сегменты. В `pages` и `entities` сначала идёт предметный слайс, затем сегменты `ui`, `api`, `model`, `lib`. Каждый слайс предоставляет публичный `index.ts`.

Импорты между слоями направлены вниз; слайсы одного слоя изолированы. Внешний код обращается к слайсу через его `index.ts`. Внутренние импорты слайса разрешены. Исключения `@x` не используются. `main.tsx` — единственный файл запуска вне слоёв; локальные импорты из него ведут в `app`.

Страницы не знают о HostProvider, runtime-конфигурации и реестре remote. Адаптеры в `app/routes` получают host-контекст и передают страницам данные, callbacks или React children. Компоненты адаптеров и router создаются один раз при `createApp`, а не при каждом рендере.

Вход и регистрация используют одну страницу с двумя режимами. Их непереиспользуемая логика остаётся в `pages/auth`. Выход и проверка готовности сессии относятся к общему layout. Отдельные features следует выделять при появлении переиспользуемого сценария, а не для заполнения слоёв.

`npm run check:architecture` проверяет структуру, направление зависимостей, изоляцию слайсов, публичные API и запрет локальных импортов за пределами `src`. Проверяются import/export, import types, строковые dynamic import и require с разрешением модулей TypeScript. Вычисляемые импорты запрещены, поскольку их границы невозможно проверить статически. Проверка включена в CI.

## Сессия и кеш

Авторизация использует HttpOnly cookies и backend API. `entities/session` содержит запросы и модель; `HostProvider` координирует жизненный цикл всего приложения.

При смене пользователя provider отменяет старые запросы, создаёт новый QueryClient, записывает подтверждённую сессию и очищает старый клиент. Изменение generation перемонтирует дерево QueryClientProvider. Ответы и уже отправленные мутации предыдущего пользователя остаются привязаны к старому клиенту.

Гостевой ключ хранится в localStorage, а при недоступном хранилище удерживается состоянием host. При первоначальной проверке сессии ключ сохраняется; при последующих сменах или принудительном восстановлении обновляется.

При `onUnauthorized` адаптер удаляет запросы корзины и перепроверяет сессию. Ожидаемый QueryClient и проверка актуальности состояния защищают от устаревшего восстановления. Принудительный reset восстанавливает также использованный гостевой ключ после выхода в другой вкладке.

## Контракт remote

React 19, TypeScript, Vite, Module Federation и TanStack Query. UI и типы интеграции поставляются tarball-пакетами `@microfronts/ui` и `@microfronts/contracts` из `vendor`. Их исходники в Shell не копируются.

Remote получают `apiBaseUrl`, `cartKey`, `queryClient`, `sessionScope`, `onUnauthorized` и `onNavigate`. Реэкспорт типов находится в `src/app/integrations/remotes/remote-props.ts`. Реестр URL остаётся только внутри Shell. Контракт props и имена exposed modules сохраняются.

Загрузка remote ограничена таймаутом 20 секунд. Suspense показывает загрузку, RemoteBoundary изолирует ошибку одного модуля; другая страница и навигация остаются доступны. Boundary перемонтируется при смене области сессии или имени remote.

## Конфигурация и инфраструктура

Подробное объяснение: [runtime-config.md](runtime-config.md). Переменные перечислены в [.env.example](../.env.example).

Vite dev middleware отдаёт `/runtime-config.json`; при сборке Vite записывает его в `dist`. Браузер читает JSON до регистрации remote. Текущий Dockerfile копирует готовый `dist` в Nginx и не генерирует конфиг при запуске контейнера. Для смены окружения без пересборки требуется отдельно заменить JSON или подключить его как файл при развёртывании.

Production build требует HTTPS-адреса remote. API может использовать `/api` на origin Shell. Reverse proxy должен сохранять Cookie/Set-Cookie; SPA fallback должен поддерживать прямые ссылки. Nginx и Render задают `no-store` для runtime-конфига. В браузерный конфиг нельзя помещать секреты.

## Проверки

В Shell: `npm run check:architecture`, `npm run typecheck`, `npm run build:local`. CI выполняет архитектурную проверку, TypeScript и production build с HTTPS-настройками.

Общий стенд и браузерные тесты находятся в отдельном репозитории `integration`. Они проверяют авторизацию, разные аккаунты, гостевую корзину, истечение сессии, прямые ссылки и отказ remote. Независимый checkout Shell не требует соседних исходников для установки и сборки.
